# Розгортання Backalor

Основний режим — віддалений API та керований PostgreSQL: [CLOUD.md](CLOUD.md). Desktop підключається через `BACKALOR_API_URL` і не запускає локальну базу. Перед відкриттям редактора потрібен перевірений Google-вхід. Бекенд підтримує приватні, публічні та спільні серверні копії проєктів. Передавання копій запускається вручну; одночасне редагування та автоматична синхронізація не реалізовані.

## Локальна розробка — лише явний development-режим

Наведені далі loopback-адреси та SQLite призначені для розробки. Для використання хмарної бази дотримуйся CLOUD.md.

## 1. Створи OAuth-клієнт

У Google Cloud Console відкрий свій проєкт → **Google Auth Platform**.

1. У **Branding** за потреби вкажи назву `Backalor`, контактну адресу підтримки й адресу розробника.
2. У **Audience** для особистого Google-акаунта вибери **External**. Якщо застосунок у режимі **Testing**, додай свою Google-адресу до **Test users**.
3. Відкрий **Clients → Create client**.
4. **Application type: Web application**, назва `Backalor`. Саме бекенд обмінює код авторизації, тому потрібен цей тип клієнта.
5. **Authorized JavaScript origins** залиш порожнім.
6. У **Authorized redirect URIs → Add URI** встав точно:

   ```text
   http://127.0.0.1:8000/auth/google/callback
   ```

7. Натисни **Create**. Скопіюй **Client ID** та **Client secret** у локальний `.env`, як описано нижче. Збережи секрет при створенні клієнта.

Офіційна інструкція: [Google OAuth для серверних застосунків](https://developers.google.com/identity/protocols/oauth2/web-server). Адреса повернення має точно збігатися: `localhost` і `127.0.0.1` є різними значеннями.

## 2. Заповни локальну конфігурацію

У корені `/Users/vladislave/Desktop/backalor-main` уже є `.env.local.example`. Якщо `.env` ще немає, скопіюй шаблон:

```bash
cp .env.local.example .env
chmod 600 .env
```

Заповни у `.env`:

```dotenv
GOOGLE_CLIENT_ID=твій-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=твій-client-secret
BACKALOR_PUBLIC_URL=http://127.0.0.1:8000
BACKALOR_DATA_DIR=backend_data
```

Секрет зберігається тільки на бекенді. Не надсилай його в чат і не включай `.env` в архіви чи репозиторій. Ім'я `.env` приховане у Finder: **Cmd+Shift+.** показує приховані файли. `.gitignore` виключає `.env`, JSON-файли клієнта, серверні дані та віртуальні середовища.

## 3. Запусти застосунок

```bash
cd /Users/vladislave/Desktop/backalor-main
BACKALOR_LOCAL_DEV=1 ./launch.command
```

У цьому development-режимі перший запуск готує `.venv-desktop` і `.venv-backend`; BackendRuntime запускає локальний API. Звичайний подвійний клік запускає хмарний клієнт, без локального API. Окремий Terminal для бекенду не потрібен.

1. На стартовому екрані натисни **Продовжити з Google**. Новий користувач створюється автоматично.
2. Заверши вхід у системному браузері та повернися до програми. До успішної авторизації редактор недоступний.
3. На екрані **Проєкти** вибери створення, відкриття папки або вкладку **Серверні копії**. Для наявної бакалаврської папки вибери `/Users/vladislave/Desktop/backalor-main`.
4. У редакторі профіль унизу бічної навігації відкриває передавання серверних копій. Адреса сервера в цьому вікні не налаштовується.
5. Для завантаження серверної копії вибери її на екрані проєктів і порожню локальну папку.

Сумісний API, запущений раніше, використовується повторно. Програма не завершує сторонній сервер або іншу копію. Власний дочірній API зупиняється при штатному завершенні програми. Логи: `backend_data/backend.log` або папка `BACKALOR_DATA_DIR`.

Після зміни `.env` потрібен перезапуск API. Якщо сервер був запущений раніше вручну, зупини саме його Terminal. `launch-backend.command` залишається засобом діагностики; для щоденної роботи він не потрібен.

При помилці запуску чи незаповненому OAuth показується помилка й повтор, без локального обходу входу. Сесія перевіряється кожні 30 секунд; відповідь API 401 блокує редактор одразу. Незастосовані дані зберігаються в чернетці. Навіть із неправильними координатами заблокований редактор можна закрити зі збереженням чернетки.

Копія містить скани, оброблені зображення, анотації та конфігурацію проєкту/обробки/YOLO. Ваги моделей і результати навчання не передаються. З прапорцем «Запам’ятати вхід» токен зберігається в захищеному сховищі ОС й перевіряється після запуску. Без прапорця сесія лише в пам’яті. **Вийти** відкликає поточну сесію на сервері; саме закриття програми не відкликає її, вона спливає через 7 діб.

Без заповнених OAuth-полів сервер запускається, але повідомляє, що Google-вхід ще не налаштований. Перевірка доступності: `http://127.0.0.1:8000/health`. Опис API: `http://127.0.0.1:8000/docs`.

## Дані та розгортання

У локальному development-режимі SQLite зберігає користувачів, хеші сесій і метадані; у хмарному — PostgreSQL. ZIP-файли — копії проєктів. Роби резервну копію всього `backend_data` при зупиненому сервері. Кожен обліковий запис бачить лише власні, публічні та явно надані йому серверні проєкти. Історія локальних папок розділена за Google-користувачами; права на самі файли визначає ОС. Конфлікт версій під час оновлення повертає 409, після чого потрібно оновити список і перевірити копію.

Локальний запуск слухає лише `127.0.0.1`. Для віддаленого розгортання використовуй Python 3.12, HTTPS reverse proxy та один процес Uvicorn:

```bash
python3.12 -m venv .venv-backend
.venv-backend/bin/python -m pip install -r requirements-backend.txt
.venv-backend/bin/python -m uvicorn backend.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Зміни `BACKALOR_PUBLIC_URL` на HTTPS-адресу сервера й зареєструй ту саму адресу з `/auth/google/callback` у Google. Встанови ліміт тіла запиту проксі щонайменше 512 MiB та достатній таймаут для сканів. Поточний API приймає ZIP до 512 MiB, до 50 000 записів і до 2 GiB розпакованих даних. Загальні квоти сховища, керування користувачами та розподілене зберігання не реалізовані. Логи проксі мають приховувати параметри callback з кодом авторизації; скрипт запуску вимикає access-log Uvicorn.

## Перевірки

```bash
QT_QPA_PLATFORM=offscreen .venv-desktop/bin/python -m unittest discover -s tests
.venv-backend/bin/python -m unittest discover -s tests_backend
QT_QPA_PLATFORM=offscreen .venv-backend/bin/python scripts/backend-desktop-smoke.py
QT_QPA_PLATFORM=offscreen .venv-backend/bin/python scripts/portal-smoke.py
```

Остання перевірка піднімає ізольований HTTP-сервер і проходить вхід, створення/оновлення/завантаження копії та відкликання сесії через десктопний клієнт. Особу Google в ній підмінено лише всередині тестового процесу. Справжній Google-вхід потрібно перевірити після створення клієнта та заповнення `.env`.

Для HTTP/UI smoke-скриптів `.venv-backend` додатково потребує GUI-залежностей: `.venv-backend/bin/python -m pip install -r requirements.txt`. Це тестове налаштування; виробничому API PyQt6 не потрібен. `portal-smoke.py` перевіряє старт перед входом, обов’язкову авторизацію, екран проєктів, ZIP-передавання та вихід. Публічного API для обходу Google-ідентифікації немає.


## Видимість і спільний доступ

Старі бази SQLite мігрують автоматично: `projects.visibility` отримує `private`, а таблиця `project_shares` зберігає права читачів і редакторів. Вхід залишається обов’язковим для всіх документів, включно з публічними.

`GET /projects` підтримує `scope=mine|public|shared|all`, `q`, `visibility=private|public`, `has_snapshot`, `sort=updated|title`, `limit` (1–500) та `offset`. `all` означає тільки доступні користувачу документи. Пошук використовує Unicode casefold; символи `%` та `_` не є шаблонами.

Власник змінює назву, опис і видимість через `PATCH /projects/{id}` з `If-Match`. Запрошення: `GET /projects/{id}/shares`, `PUT /projects/{id}/shares` з `email` та `role=reader|editor`; відкликання — `DELETE /projects/{id}/shares/{user_id}`. Користувач з цим email має вже існувати після Google-входу. Листи та повідомлення не надсилаються. Редактор може оновлювати ZIP, читач — лише завантажувати; керування доступом і видалення залишаються у власника. Права на запис перевіряються повторно після отримання ZIP.

Перезапусти бекенд після оновлення коду, щоб завантажилися нові маршрути й міграція. Поточні серверні документи не публікуються автоматично. Переносна бібліотека `results/cipher_library.json` тепер також дозволена у серверних ZIP; PNG-зразки каталогу містяться в `project.json`.
