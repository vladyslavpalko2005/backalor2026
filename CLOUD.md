# Хмарний Backalor: API + PostgreSQL + Google-вхід

Код і конфігурація підготовлені; хмарні ресурси ще не створені. Потрібні твій акаунт Render, репозиторій із серверним кодом і Google OAuth-клієнт. Не публікуй `.env`, скани, `backend_data` або віртуальні середовища.

## Архітектура

```text
Desktop Backalor → HTTPS API на Render → керований PostgreSQL
                              ↓
                    постійний диск ZIP-копій
```

Desktop отримує лише адресу API. Google secret, пароль PostgreSQL, користувачі, серверні сесії, метадані й права доступу знаходяться на сервері. Диск API зберігає скани/анотації у ZIP, а PostgreSQL — записи про них. На комп’ютері залишаються робочі локальні проєкти та захищений запис входу; сервер або база не запускаються при заданому `BACKALOR_API_URL`.

## Перший деплой

1. Створи акаунт [Render](https://dashboard.render.com/) і приватний репозиторій GitHub/GitLab для сервера.
2. Виконай `python3 scripts/package-cloud.py`. Архів `dist/backalor-cloud-source.zip` містить тільки серверні вихідні файли й конфігурацію. Розпакуй їх у корінь репозиторію; `.env` та користувацькі дані до архіву не входять.
3. У Render створи **New → Blueprint**, підключи репозиторій і переглянь `render.yaml`. Він описує API, керований PostgreSQL і постійний диск ZIP. Використовуються платні плани — остаточну вартість перевір у Render перед створенням ресурсів. Цей код сам не оплачує й не створює ресурси.
4. У значеннях `GOOGLE_CLIENT_ID` і `GOOGLE_CLIENT_SECRET` вкажи Web application OAuth-клієнт. На першому етапі можна створити сервіс, отримати його HTTPS-домен і після цього завершити налаштування OAuth.
5. У Google Cloud додай точний callback `https://ТВІЙ-СЕРВІС.onrender.com/auth/google/callback`. Якщо OAuth-застосунок у Testing, додай свій Google-акаунт до Test users. Після зміни секретів перезапусти сервіс.
6. Render автоматично передає внутрішній PostgreSQL URL і `RENDER_EXTERNAL_URL`. Статичний домен у коді не потрібен. Для власного домену задай `BACKALOR_PUBLIC_URL=https://api.example.org` і відповідний callback у Google.
7. Перевір `https://ТВІЙ-СЕРВІС.onrender.com/ready`: очікується `{"status":"ok","database":"postgresql"}`. `/health` додатково показує `google_configured: true` після налаштування OAuth.
8. На desktop додай **тільки** цей рядок у свою `.env`, зберігши інші власні налаштування:

   ```dotenv
   BACKALOR_API_URL=https://ТВІЙ-СЕРВІС.onrender.com
   ```

   Запусти `./launch.command`. У хмарному режимі launcher не встановлює середовище бекенду і не запускає локальний API чи SQLite. Альтернатива: `.venv-desktop/bin/python -m app.main --server https://ТВІЙ-СЕРВІС.onrender.com`.

Без `BACKALOR_API_URL` звичайний запуск показує помилку налаштування хмари та не створює локальну базу. Старий development-режим доступний лише явно: `BACKALOR_LOCAL_DEV=1 ./launch.command` або `python -m app.main --local-backend`.

За бажанням установи та підключи інтеграцію Render у цьому середовищі, щоб продовжити деплой з асистентом після створення акаунта. Сам факт наявності `render.yaml` не означає виконаного деплою.

## Зручна реєстрація й повторний вхід

Окремої форми реєстрації немає: перший Google-вхід автоматично створює акаунт, наступні знаходять його за стабільним Google ID.

Прапорець **Запам’ятати вхід на цьому комп’ютері** зберігає сесію в macOS Keychain, Windows Credential Locker або Linux Secret Service. Короткий локальний JSON містить лише адресу сервера та підказку профілю. Токен не записується до нього, до проєктів або ZIP.

При наступному запуску застосунок спочатку перевіряє токен через `/auth/me`. До перевірки редактор заблокований. При відмові 401 збережений вхід забувається; при втраті мережі його можна повторити. **Вийти** відкликає сесію на сервері й прибирає локальний запис. Якщо системне сховище недоступне, Google-вхід продовжує працювати в межах поточного запуску, а інтерфейс повідомляє, що запам’ятовування не вдалося.

Сесія зараз діє до 7 днів — це збереження входу до серверного строку дії, а не безстроковий доступ. На спільному комп’ютері вимкни прапорець.

`localStorage` є браузерним API; у цьому PyQt desktop-застосунку браузерного сховища немає. Системне сховище виконує потрібну функцію повторного входу. [OWASP рекомендує не зберігати ідентифікатори сесій у browser localStorage](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html).

## Сховище та резервні копії

- `BACKALOR_DATABASE_URL` — PostgreSQL URL тільки на сервері. У Docker задано `BACKALOR_REQUIRE_POSTGRES=1`: за відсутності URL або зв’язку з БД запуск зупиняється, SQLite не створюється.
- `BACKALOR_DATA_DIR=/var/data` — постійний диск ZIP-копій. Це не папка бази даних. Не замінюй його ефемерним файловим сховищем контейнера.
- База і сервіс знаходяться в одному регіоні Frankfurt. Зовнішні підключення PostgreSQL вимкнені в шаблоні (`ipAllowList: []`); desktop не підключається до БД напряму.
- Залиш один API-інстанс, поки ZIP зберігаються на прикріпленому диску. Перехід на кілька інстансів потребуватиме спільного object storage.
- Резервуй і PostgreSQL, і ZIP-диск; резервна копія лише одного з них не відновлює повний сервер. Відновлення перевіряй окремо перед використанням для архівного матеріалу.
- Для сумісності старого локального сервера SQLite лишився лише як явний development-шлях без `BACKALOR_REQUIRE_POSTGRES=1`. Хмарний шаблон його не використовує.

## Перенесення старого локального сервера

Новий Google-вхід у чистій хмарній базі працює одразу. Щоб перенести наявні акаунти, серверні проєкти й права:

1. Зупини старий API й зроби резервну копію `backend_data`.
2. Передай копію SQLite та `snapshots/` у тимчасову папку хмарного сервера через захищений канал. Не додавай їх до Git-репозиторію.
3. Переконайся, що цільовий PostgreSQL порожній. На сервері з налаштованим `BACKALOR_DATABASE_URL` виконай:

   ```bash
   python -m backend.migrate_postgres \
     --source /tmp/legacy/backalor.sqlite3 \
     --source-snapshots /tmp/legacy/snapshots \
     --target-snapshots /var/data/snapshots
   ```

4. Скрипт перевірить ZIP, збереже ID/версії/приватність/учасників і не перезаписуватиме непорожню базу чи наявні файли. Старі токени та незавершені OAuth-запити не переносяться; користувачі входять заново. При невдалому записі створені копії ZIP прибираються, транзакція БД відкочується.
5. Після перевірки результату видали тимчасову копію старої бази з сервера. Оригінал і резервна копія на твоєму комп’ютері залишаються до завершення перевірки.

## Оптимізації

Список документів отримує права одним SQL JOIN, Unicode-пошук використовує підготовлені поля, індекси допомагають сортуванню та відбору власника. Глобальний пошук за входженням підрядка поки не є повнотекстовим індексом для великого корпусу.

Порівняння контурів використовує бітові маски замість множин, кешує нормалізовані зразки й повторні запити, не дублює шаблони та вибирає лише два найкращі варіанти. Відповідність початковому алгоритму перевіряється автоматично.

Офіційні джерела для конфігурації: [Render Blueprint](https://render.com/docs/blueprint-spec), [постійні диски](https://render.com/docs/disks), [PostgreSQL](https://render.com/docs/postgresql), [плани ресурсів](https://render.com/docs/compute-plans), [автоматичний HTTPS-домен](https://render.com/docs/environment-variables).
