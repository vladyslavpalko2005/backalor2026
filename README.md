# Backalor — десктопний редактор історичних шифрувальних документів

Десктопний застосунок на Python/PyQt6 для підготовки сканів, ієрархічної анотації та експериментів із YOLO. Інтерфейс українською і словацькою. Вхід через Google обов’язковий. Застосунок підключається до хмарного FastAPI API з PostgreSQL, який підтримує приватні, публічні та спільні серверні копії проєктів: [налаштування й запуск](DEPLOYMENT.md).

## Запуск на цьому Mac

Двічі натисни `Запустити Backalor.command` на Робочому столі або `launch.command` у цій папці. Встановлено окреме справне середовище `.venv-desktop` із PyQt6, Pillow, PyMuPDF та Ultralytics. Старе `.venv` містило Linux-шляхи й не використовується.

```bash
.venv-desktop/bin/python -m app.main --project .
```

Для нового встановлення підготуй хмарний API за [CLOUD.md](CLOUD.md) і задай `BACKALOR_API_URL` у `.env`. Google OAuth і PostgreSQL налаштовуються тільки на сервері. Основний запуск на macOS готує середовище редактора:

```bash
./launch.command
```

`launch.command` призначений для macOS. Для Google-входу та перевірки сесії потрібна мережа. На інших ОС потрібен адаптований запуск відповідних середовищ; поточний сценарій перевірено на macOS.

## Робочий процес

1. Увійди через Google. На екрані **Проєкти / Projekty** відкрий або створи проєкт. Новий проєкт створюється в порожній папці. Назву, опис і архівне джерело можна доповнити в метаданих проєкту.
2. Імпортуй зображення або PDF. PDF перетворюється на сторінки PNG із 150 dpi. Сторінки одного PDF автоматично отримують спільну групу документа. Однакові назви не перезаписують наявні зображення чи анотації.
3. У **Скани / Skeny** налаштуй послідовність обробки, порівняй оригінал і результат, збережи конфігурацію й оброблені зображення.
4. У **Розмітка / Anotovanie** створи L1 (секцію), L2 (пару), L3 (елемент). Нові L2 повинні бути всередині L1, нові L3 — всередині L2. Старі JSON читаються без автоматичної зміни їхньої структури.
5. Вимкни **Малювати рамки / Kresliť rámčeky**, щоб вибирати й переміщувати рамки. Перетягування будь-якого кута вибраної рамки змінює розмір. У властивостях можна точно задати x/y/w/h, батьківську анотацію, транскрипцію, код, тип і примітки. Зміни зберігаються при переході до іншої рамки або скану. Можна також натиснути **Застосувати / Použiť** чи **Відкинути зміни / Zahodiť zmeny**. Некоректні координати блокують перехід до виправлення або відкидання змін.
6. **Символи / Symboly** показує фрагменти L3 з усіх зображень проєкту. Шукай за назвою зображення, транскрипцією, кодом, типом або примітками. Двічі натисни рядок, щоб перейти до відповідної рамки.
7. Запусти перевірку анотацій із меню проєкту. Вона показує неправильних батьків, вихід за межі й дублікати ID, не змінюючи даних.
8. Експортуй YOLO, COCO або весь проєкт у ZIP. ZIP можна імпортувати в порожню папку на іншому комп’ютері.

Анотації завжди задані в пікселях **оригіналу**. Обрізка, поворот і масштабування в попередньому перегляді не пересувають рамки. Евристична автоанотація використовує лише операції, які не змінюють геометрію; YOLO працює над оригіналом. Це усуває попередню неоднозначність між координатами оброблених сканів і вихідними зображеннями.

Анотації автоматично зберігаються кожні 10 секунд (коли немає незастосованих властивостей), під час переходу між зображеннями, зміни проєкту та закриття вікна. Незастосовані властивості зберігаються в чернетці відновлення. Збереження виконується лише після змін. Undo/redo охоплює додавання, видалення, зміни рамок, властивостей і результати автоанотації; історія обмежена 100 діями на поточному зображенні.

### Керування

- Колесо миші: масштаб; **Вмістити / Prispôsobiť**, клавіша `F`: умістити зображення.
- `1`, `2`, `3`: рівень анотації. Прапорці L1/L2/L3: видимість шарів.
- Стандартні системні комбінації Save / Undo / Redo (на Mac: Cmd-S / Cmd-Z / Cmd-Shift-Z).
- Delete при фокусі на полотні: видалити вибрану анотацію та її дочірні об’єкти.
- Контекстне меню зображення: задати групу документа або перемістити зображення й його анотації до `.trash/`. Кошик можна відновити вручну.

## Моделі, навчання та оцінювання

У вкладці **Моделі й навчання / Modely a tréning** обери локальні `.pt` для L1/L2/L3 і пороги впевненості. Параметри зберігаються в `results/yolo_config.json`. Наявні ваги `train4`, `train5`, `train6` підключені через попередню конфігурацію.

На новому комп’ютері встанови додаткові залежності:

```bash
.venv-desktop/bin/python -m pip install -r requirements-ml.txt
```

Експорт YOLO тепер створює різні `images/train`, `images/val`, `images/test` із seed 42, приблизно 70/15/15 за кількістю документів. Для експорту потрібно щонайменше три анотовані документи. Сторінки одного PDF або однієї вручну заданої групи не розділяються між вибірками. Для старих сканів без групи кожне зображення вважається окремим документом: перед дослідницьким експериментом правильно задай групи через контекстне меню.

Усі рівні використовують однаковий поділ. Зображення без об’єктів конкретного рівня включаються як негативні приклади з порожнім TXT. L3 із міткою `not_symbol` не стають позитивними прикладами. Експорт використовує оригінальні зображення, оновлює їхні копії, перевіряє межі рамок; попередній успішний експорт залишається в `L1.previous` / `L2.previous` / `L3.previous`.

Обери рівень, епохи, розмір входу й batch, натисни **Навчати / Trénovať**. Навчання йде в окремому процесі, вивід видно у вкладці; процес можна зупинити. Після успішного навчання шлях до нових `best.pt` автоматично записується у конфігурацію. **Оцінити test / Vyhodnotiť test** запускає оцінювання на окремій test-вибірці. Старі експорти з `train: images`, `val: images`, `test: images` для цього потрібно створити заново.

Логи останнього процесу зберігаються в `results/training.log`; експерименти — у `runs/detect/` та `runs/evaluate/`. Довгі операції (імпорт PDF, пакетна обробка, автоанотація, експорт YOLO, OCR) виконуються у фоні. Під час задачі редагування заблоковане; перед закриттям слід дочекатися завершення, для навчання доступна кнопка зупинки.

## Розпізнавання тексту

Ручна транскрипція працює без моделей. Для TrOCR:

```bash
.venv-desktop/bin/python -m pip install -r requirements-ocr.txt
```

Укажи **локальну папку повної моделі TrOCR** із конфігурацією, processor/tokenizer та вагами. Вибери рамку й натисни **Розпізнати текст фрагмента / Rozpoznať text výrezu**. Модель завантажується з `local_files_only=True`; застосунок не завантажує її автоматично. Результат потрібно перевірити вручну. Ваг TrOCR у наданому проєкті немає, тому реальне розпізнавання не перевірялося.

## Дані та сумісність

```text
images_raw/              оригінальні зображення / сторінки PDF
images_processed/        результати попередньої обробки
annotations/             ієрархічні JSON, schema_version 4
project.json             метадані та групи документів
models/                  довільні локальні моделі
results/                 конфігурації, експорти, логи
runs/                    результати навчання
.trash/                  вилучені зображення й анотації
```

COCO використовує стандартні зображення/категорії/bbox і додаткові `parent_id`, `source_id`, `attributes` для ієрархії та транскрипції. Сторонній інструмент може ігнорувати ці розширення. YOLO TXT не зберігає ієрархічних зв’язків; їхнім першоджерелом залишається JSON.

ZIP переносить зображення, анотації та конфігурації, але не великі навчені моделі. Після перенесення перевір шляхи до ваг. Імпорт ZIP відхиляє вихід за межі папки та запис у непорожній проєкт. Одночасне редагування тієї самої папки кількома запущеними застосунками не підтримується.

## Перевірки

```bash
QT_QPA_PLATFORM=offscreen .venv-desktop/bin/python -m unittest discover -s tests -v
```

Автоматизовані перевірки охоплюють збереження, зворотну сумісність, рамки, undo/redo, експорт, поділ документів, імпорт PDF, ZIP, пошук, мови й фонову задачу. Додатково перевірено реальну каскадну детекцію на наявних вагах і тестове навчання в тимчасовому проєкті; подробиці в пакеті результатів на Робочому столі.

## Уточнення інтерфейсу

Перегляд має три режими: порівняння, оригінал, результат. Колесо й кнопки +/− змінюють масштаб; перетягування переміщує скан. «100%» показує піксельний масштаб, «Вмістити» — весь скан. Синхронний перегляд пов’язує центри й масштаб двох зображень. На вузьких вікнах порівняння складається вертикально.

Панель інструментів рамок показується у вкладці анотацій. Режими «Малювання» та «Вибір і редагування» задаються явно. Ієрархія та властивості мають окремі вкладки; меню автоанотації й експорту завжди доступні під ними. Alt-перетягування або середня кнопка миші переміщують полотно навіть у режимі малювання.

Скани впорядковані природно: img1, img2, …, img10. Кнопки попереднього/наступного скану враховують пошук. Клавіші 1/2/3, F та Delete діють тільки при фокусі на полотні й не заважають вводити текст у властивостях.

## Каскадні навчальні дані YOLO

Новий експорт узгоджено з каскадною детекцією:

| Модель | Навчальний вхід | Об’єкти |
|---|---|---|
| L1 | Повний оригінальний скан | Секції |
| L2 | Вирізка кожної секції L1 | Її пари L2 |
| L3 | Вирізка кожної пари L2 | Її елементи L3 |

Координати YOLO перераховуються відносно вирізки. `manifest.json` містить початкову сторінку, групу документа, ID батьківського елемента, межі вирізки й ID об’єктів. Поділ train/val/test виконується **до створення вирізок**, за документами: вирізки одного документа не потрапляють у різні вибірки.

Батьківські області без позитивних дочірніх об’єктів зберігаються як негативні приклади з порожнім TXT. Перед експортом перевіряються батьківські зв’язки й межі рамок. Неправильна ієрархія зупиняє експорт із переліком проблем; анотації не виправляються автоматично. У кожній вибірці мають бути потрібні батьківські області. Однакові імена джерел без розширення відхиляються, щоб не перезаписати мітки.

Панель навчання та CLI перевіряють маніфест і поділ даних. Старий експорт цілих сторінок для L2/L3 треба створити заново. **Старі навчені ваги не стають каскадно навченими від самого експорту**: для узгодженого експерименту перенавчи L2/L3 на нових вирізках. Технічні запуски однієї епохи перевіряють інтеграцію; їхні метрики не є дослідницьким результатом.

## Автозбереження та відновлення

- Після паузи приблизно в одну секунду зміни записуються в `.recovery/<скан>.json`. Періодичний таймер також оновлює чернетку кожні 10 секунд.
- Чернетка містить стан усіх рамок і незастосовані властивості, включно з тимчасово неправильними координатами. Таймер не відкриває модальних помилок під час введення.
- Застосовані зміни записуються в основний JSON кожні 10 секунд. Основні записи й чернетки використовують тимчасовий файл, `fsync` та атомарну заміну.
- Перед зміною основного JSON попередній читабельний файл зберігається в `annotations/<скан>.json.bak`. При видаленні всіх рамок записується порожній JSON, а попередні рамки залишаються в резервній копії.
- Після аварії при відкритті відповідного скану програма запропонує відновити чернетку. Якщо основний JSON пошкоджено, доступне відновлення з резервної копії.
- Якщо основний файл змінився після завантаження, запис зупиняється, а чернетка залишається. Меню **Проєкт → Перезавантажити анотації з диска** дозволяє завантажити збережену версію, залишивши власні зміни в чернетці.
- Одночасне редагування одного проєкту кількома застосунками все ще не є підтримуваним спільним режимом. Перевірка версії захищає основний файл від виявленого зовнішнього оновлення, але не замінює багатокористувацьке сховище.

## Журнал аварій

Python-винятки й стеки нативних аварій записуються в `results/application_crash.log`. Після оновлення коду перезапусти програму, щоб нові обробники та діагностика завантажилися.

## Оцифрування ключа

Вкладка **Перевірка / Kontrola** додає наступні етапи після L1–L3: роль тексту, тип елемента, розпізнавання за типом, ручне підтвердження й ключ JSON/CSV. Роль `plaintext/ciphertext` задається окремо від типу `readable/cipher_symbol`. Автоматична класифікація типів і символів працює за перевіреними зразками локальної бібліотеки або власними навченими моделями; TrOCR — локальної моделі й залежностей `requirements-ocr.txt`. Ручний процес доступний без них.

[Порівняння зі схемою, порядок роботи й підготовка навчальних даних](PIPELINE.md).

## Процес анотації за CipherAnnotation

Єдине дерево L1–L3 з пошуком і дублюванням гілок, іменовані групи, пакетне редагування L3, каталог кодів символів з еталонними входженнями та явні зв'язки символів із текстом. Каталог відкривається через **Символи → Каталог символів**, пакетні зміни — через **Перевірка → Змінити вибрані…**.

[Аналіз вебпроєкту, реалізовані можливості та інструкція](CIPHERANNOTATION_COMPARISON.md).

## Спрощений інтерфейс

- **Скани** — додай зображення/PDF; праворуч налаштуй обробку. Результат зберігається через **Зберегти обробку**.
- **Розмітка** — сторінки й дерево ліворуч, скан посередині, властивості праворуч. Початковий режим — **Вибирати**. Для нової рамки вибери **Малювати** та рівень. Координати, підпис і примітки — у **Додаткових властивостях**.
- **Перевірка** — відфільтруй пропуски або неперевірені елементи. **Наступний неперевірений** відкриває відповідну рамку з наближенням. Автоматичне розпізнавання розгортається окремо.
- **Експорт** угорі — ключ JSON/CSV, ZIP проєкту, COCO, YOLO та навчальні фрагменти.
- **Інструменти → Моделі та навчання** — ваги, TrOCR і навчання. **Як працювати** відкриває коротку підказку прямо у вікні.
- Профіль унизу темної бічної панелі — серверні копії та вихід із сесії. **Проєкти** повертає до списку локальних і серверних проєктів.

## Обов’язковий вхід і проєкти

`launch.command` перевіряє хмарний API. Звичайний запуск не створює локальний бекенд або базу; за відсутності URL показує налаштування хмари. Поле адреси сервера та ручне підключення у звичайному інтерфейсі прибрані. Увійди через Google, потім створи проєкт, відкрий папку або вибери серверну копію. Новий Google-користувач реєструється автоматично.

Щоб продовжити наявні анотації, на екрані проєктів натисни **Відкрити папку…** та вибери `/Users/vladislave/Desktop/backalor-main` або свою іншу папку проєкту. Дані залишаються на своїх місцях.

З прапорцем «Запам’ятати вхід» сесія зберігається в системному захищеному сховищі та перевіряється сервером після перезапуску. Без прапорця потрібен повторний Google-вхід. Для Google-входу та перевірки сесії потрібна мережа. При втраті доступу до сервера редактор блокується зі збереженням чернетки. Списки останніх папок розділені за обліковими записами; самі локальні файли захищаються правами ОС.

## Шифротексти та пошук відповідних ключів

На вкладці **Перевірка / Kontrola** доступні **Експорт шифротексту…** і **Бібліотека та відповідності…**. Це локальна бібліотека знімків документів: можна додати поточний проєкт як ключ або шифротекст, а також імпортувати JSON, експортовані з інших проєктів Backalor. Вибери будь-який документ і натисни **Знайти відповідності**: для шифротексту порівнюються ключі, для ключа — шифротексти.

Оцифрування шифротексту:

1. Імпортуй скан/PDF, створи L1 для розділів, L2 для рядків і L3 для окремих символів або читабельних токенів. Для документа з кількох сторінок використовується природний порядок назв сканів.
2. Задай роль **Шифротекст** на L1 або окремих L3. Вона успадковується дочірніми елементами. Для кожного L3 вибери тип і введи код символу або транскрипцію; перевір результат. Ручна робота не потребує моделей; автоматичне розпізнавання використовує наявні локальні моделі й теж потребує перевірки.
3. Експортуй JSON або CSV. JSON зберігає розділи, рядки, послідовність токенів, ID та координати першоджерела, роль, тип, перевірку й проблеми. CSV містить один токен на рядок. Розділи й рядки впорядковано згори вниз, символи в кожному рядку — зліва направо. Для іншого напрямку письма цей порядок поки не підходить. Автоматична детекція L2, навчена на парах ключів, не гарантує правильного виділення рядків шифротексту: перевір рамки або створи їх вручну.
4. Додай документ у бібліотеку. Для кількох незалежних документів використовуй окремі проєкти та імпорт їхніх JSON. Ключі зберігають попередню структуру L1–L3; для шифротекстів L2 виконує роль рядка.

Пошук використовує **точний збіг узгоджених кодів символів**, з урахуванням регістру. `S1` і `S10` — різні токени; `42`, транскрибоване одним L3, — один токен, а не дві цифри. Однаковий код у різних документах має позначати той самий символ. Зіставлення рисунків символів, автоматичне узгодження різних каталогів і мовна оцінка розшифрування не реалізовані.

У ключі використовуються перевірені пари без помилок. Кілька шифросимволів при одному відкритому тексті вважаються гомофонами. Якщо відкритих текстів у парі кілька, потрібен явний зв’язок **Пов’язаний відкритий текст** для кожного шифросимволу; відповідність не вгадується. Конфліктні розшифрування одного коду показуються як `[A / B]`.

Результати ранжуються за часткою перевірених токенів шифротексту, відомих ключу, потім за кількістю різних відомих кодів і відомих входжень. Таблиця показує обидва лічильники; нижче — невідомі коди, неоднозначності, виключені токени та попереднє розшифрування по рядках. Неперевірені/неповні токени й токени сторінок із помилками структури виключаються. Якщо придатних токенів немає, покриття дорівнює нулю. **Покриття не є ймовірністю правильності ключа:** навіть 100% означає лише сумісність за кодами, а не доведену відповідність історичному документу.

Бібліотека зберігається в `results/cipher_library.json` і входить у ZIP проєкту. Це знімки: після змін анотацій додай новий знімок; однаковий знімок не дублюється. Виявлені зовнішні зміни бібліотеки блокують запис до її повторного відкриття. Імпорт підтримує JSON ключів Backalor версії 1 і JSON шифротекстів версії 1; CSV, COCO та експорти CipherAnnotation напряму не імпортуються.

Перевірено вихідний код [CipherAnnotation, commit 8c026cc](https://github.com/jurajglatz/CipherAnnotation/tree/8c026cc1bc2102a640ca3b125e84676698490c41/CipherAnnotation): каталог і зв’язки символів узгоджуються з поточним підходом, але готового алгоритму відповідності ключів шифротекстам у перевіреній версії не знайдено. Описаний пошук — окрема базова реалізація Backalor.


## Бібліотека, рукопис і перенесення налаштувань

- **Символи → Каталог символів** — окрема вкладка з кодами, описами, входженнями та імпортованими зразками. **Експорт бібліотеки…** створює переносний JSON із PNG-фрагментами перевірених шифросимволів і читабельних елементів. **Імпорт бібліотеки…** об’єднує бібліотеки: однакові коди означають той самий символ, наявні непорожні описи зберігаються. PNG-зразки працюють без вихідних сканів. Видалення опису не видаляє імпортовані зразки.
- **Перевірка → Автоматичне розпізнавання → Розпізнати за бібліотекою** — порівнює порожні/невизначені L3 з перевіреними фрагментами. Розрізняє `readable` та `cipher_symbol`, пропонує відому транскрипцію або код. Потрібні і мінімальна схожість, і відрив від другого варіанта. Порожні зображення, неоднозначні та слабкі збіги не отримують автоматичної мітки. Уже заповнені або підтверджені результати зберігаються. Зміни можна скасувати Undo; пропозиції потрібно перевірити вручну.
- Для **нового рукописного тексту**, якого немає серед зразків, вибери локальну TrOCR у **Інструменти → Моделі та навчання**, задай L3 тип `readable` і натисни **Розпізнати L3 за типом**. Потрібні залежності `requirements-ocr.txt` і повна локальна модель. Класифікатор символів `.pt` може записувати лише коди, наявні в локальному каталозі або анотаціях проєкту; невідомі коди залишаються непідтвердженими.
- **Інструменти → Експорт / Імпорт налаштувань…** переносить послідовність обробки, шляхи моделей і пороги розпізнавання. Ваги моделей, облікові дані та сесії до цього JSON не входять. Після імпорту перевір шляхи на новому комп’ютері. Попередні конфігурації зберігаються у `.json.bak`.

Зіставлення зі зразками — консервативне порівняння нормалізованих контурів, а не універсальний OCR чи навчена нейромережа. Якість на нових почерках потребує окремого дослідження. Локальні моделі не завантажуються автоматично.

## Публічні та спільні документи

На екрані **Проєкти** є вкладки **На цьому комп’ютері**, **Серверні копії**, **Публічні**, **Спільні** та **Усі доступні**. Пошук за назвою/описом враховує українські й словацькі літери. Фільтри задають видимість, наявність ZIP і порядок сортування; списки мають сторінки по 100 записів.

Власник серверної копії відкриває **Доступ і учасники…** на екрані проєктів або в діалозі облікового запису редактора:

- **Приватний** — доступ власнику та явно запрошеним користувачам. Наявні серверні проєкти при оновленні залишаються приватними.
- **Публічний** — усі користувачі Backalor, які увійшли, можуть знайти й завантажити скани та анотації. Публічність не дає права змінювати серверну копію.
- **Спільний** — власник надає доступ за email Google користувачу, який уже хоча б раз увійшов у Backalor. **Читання** дозволяє отримати локальну копію; **Редагування серверної копії** також дозволяє оновити ZIP. Керувати учасниками, публічністю та видаленням може тільки власник.

Доступ можна відкликати; подальші серверні операції перевіряють актуальні права. Завантажені локальні копії залишаються у користувачів. Оновлення ZIP і метаданих використовують версії: конфлікт вимагає оновлення списку. Це обмін знімками, а не одночасне редагування однієї папки чи автоматичне злиття змін.

## Хмара, база й повторний вхід

[Покрокове розгортання API та керованого PostgreSQL](CLOUD.md). Готові `Dockerfile` і `render.yaml`; серверний архів створюється через `python3 scripts/package-cloud.py`. Хмарний акаунт і OAuth-домен треба налаштувати перед першим реальним деплоєм. Код сам не створює платних ресурсів.

Звичайний desktop-запуск потребує `BACKALOR_API_URL=https://...`; локальну базу не запускає. Старий development-режим доступний явно: `BACKALOR_LOCAL_DEV=1 ./launch.command` або `python -m app.main --local-backend`.

Google автоматично реєструє нового користувача. Опція **Запам’ятати вхід на цьому комп’ютері** використовує macOS Keychain / Windows Credential Locker / Linux Secret Service. Локальні JSON зберігають лише підказку профілю; токен не записується в проєкти або звичайні файли. Перед відкриттям проєктів після перезапуску виконується `/auth/me`; вихід відкликає й забуває сесію.
